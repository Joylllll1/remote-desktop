# 画面传输与验收

## 当前源码的传输方式

协议 v4 用连续发送替代 v3 的逐帧请求：客户端启动一次画面流，共享端按最多 10 帧/秒采集和发送；客户端按顺序解码并确认收到的画面。键鼠输入继续独立发送，不必等当前画面传完。

这不是无限发送。共享端最多保留 3 个未确认画面，未确认数据通常不超过 512 KiB（含封装）；超过字节额度的单张画面只能独占窗口，图像数据仍受 12 MiB 上限限制。没有额度时停止采集，恢复额度后再采集当前桌面，不排队保存一串旧截图。无法提前知道编码大小时，超出剩余额度的候选画面会被丢弃，并重置编码基线，等窗口清空后重新采集。局部更新依赖之前的画面，因此已发送的补丁必须按顺序解码；不能随便丢弃网络中的某个补丁。

分辨率选择仍为宽度上限 1920 / 1280，保持屏幕比例，不自动降低画质。改变分辨率时，客户端先解码并确认已在途的旧规格画面，再展示新规格画面。

查看器详情会明确显示是否启用了“连续画面传输（协议 v4）”。新版查看器兼容 v1–v3 共享端，但连接旧共享端时仍使用旧传输方式。旧查看器不支持 v4 共享端；使用新协议需要两端一起更新。

## 仍然存在的限制

- 仍使用 TCP、JPEG 完整画面和 PNG 局部更新，不是硬件视频编码方案，不适合视频或游戏。
- 初始完整画面仍须传完才能显示。低带宽传输大画面时，连续发送不能缩短其必需的传输时间。
- TCP 中已经发送的字节无法被后来的新画面跳过；网络严重阻塞或重传时，仍会延迟。帧数和字节额度限制的是积压量，不是延迟上限。
- 键鼠独立发送不意味着能绕过断网；客户端画面过期暂停控制、共享端按键超时释放等保护仍然保留。
- 代码测试不能证明校园网直连、Tailscale 中转路径或真实 Windows 采集驱动稳定。

## 本地可重复的对照测试

在仓库根目录、安装项目依赖后运行。测试只使用本机 socket 和合成 1920×1080 桌面，不读取真实屏幕、不操作真实键鼠、不连接 Tailscale 设备。

```sh
.venv/bin/python -m unittest discover -v

# 新旧协议使用相同的 300 ms 往返延迟、256 KiB/s 下行
.venv/bin/python tools/benchmark_stream.py --seconds 12 --output /tmp/stream-comparison.json

# 限速到 16 KiB/s，观察首帧等待及后续小范围更新
.venv/bin/python tools/benchmark_stream.py --versions 4 --kib-s 16 --seconds 12

# 传输中暂停下行 3 秒，观察恢复后的画面年龄
.venv/bin/python tools/benchmark_stream.py --versions 4 --stall-seconds 3 --seconds 12
```

Windows 将 `.venv/bin/python` 换为 `.\.venv\Scripts\python.exe`，输出路径换为本机可写路径。

工具报告首帧时间、解码帧率、采集到解码的画面年龄、帧间最长间隔、合成输入到达时间和线程清理结果。传播延迟与限速在有界队列的双向字节中继中模拟，不是给每一帧简单增加 sleep。解码帧率不等于真实界面显示帧率；合成输入到达不等于 Windows 应用完成操作。

真实验收仍需记录两端版本、实际连接路径、接收分辨率，并在 Windows 桌面上验证持续操作、清晰度、断线恢复和键鼠释放。不能以“首帧出现”或一次 ping 成功作为稳定性的结论。

## 本次合成测试结果

下表来自 macOS ARM64、Python 3.12 的本地模拟；完整机器可读记录在 [transport-results.json](transport-results.json)。画面为文档界面中的小范围变化，不能代表滚动网页、视频或真实 Windows 采集性能。

| 条件 | v3 逐帧请求 | v4 连续传输 |
| --- | ---: | ---: |
| 300 ms RTT、256 KiB/s，首帧后测量约 12 秒 | 3.15 解码帧/秒 | 9.47 解码帧/秒 |
| 同一条件的首帧等待 | 1.47 秒 | 1.47 秒 |
| 同一条件的画面年龄 P95（采集到解码） | 0.171 秒 | 0.168 秒 |
| 同一条件的合成输入到达 P95 | 0.156 秒 | 0.156 秒 |

v4 在 16 KiB/s、300 ms RTT 下首次完整画面仍等待 **13.66 秒**。随后观察约 15 秒，期间人为暂停下行 3 秒，最大帧间隔为 3.07 秒，结束时画面年龄恢复至 0.19 秒；无会话错误和遗留测试线程。暂停期间的旧画面仍可能延迟到达，不能把“恢复”理解为传输中没有停顿。

另外使用真实 v4 会话连接测试查看器恢复逻辑：强制断开 socket 后能重连、解码新的完整画面并继续传递合成输入。它验证代码的恢复路径，不代表真实 Wi-Fi 或校园网连接已修复。
